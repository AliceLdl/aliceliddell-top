# 总统模拟器 · AI 版（president-sim-ai）

> 在原版《美国总统模拟器 v0.2.2》之上复制出来的一层「AI 裁决引擎」：
> **行动和选项不再由游戏内置，改成你自己写。** 你写一句话，AI 判断它在现实美国政治里会怎么发生，
> 再把结果换算成游戏认识的数值，交回原版引擎结算。
>
> 原版那 4MB 的单体脚本**一行未改**——选举、国会、经济冲量队列、州级情绪、法案排期、
> 最高法院、危机树、存档格式全部沿用。AI 层只是替换了「行动台 / 事件决断 / 冲击节点 /
> 危机处置」这四个入口，并把结果喂回原版的 `applyFx` 等函数。

## 一分钟上手

1. **起一个本地静态服务**（`file://` 打开时浏览器会拦跨域请求，不能调 API）：

   ```powershell
   cd aliceliddell-top-site\president-sim-ai
   python -m http.server 8080
   # 打开 http://127.0.0.1:8080
   ```

   部署到 Cloudflare Pages / GitHub Pages 时，把整个 `president-sim-ai/` 目录原样传上去即可，
   访问路径 `/president-sim-ai/`。

2. 进游戏 → 顶栏右侧点 **`AI ●`** → 填接口：

   | 服务商 | 接口地址（base URL） | 模型示例 |
   |---|---|---|
   | DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
   | OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
   | Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
   | 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
   | 阿里 Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
   | SiliconFlow | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
   | OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-3.5-sonnet` |
   | Anthropic | `https://api.anthropic.com` | `claude-sonnet-4-20250514` |
   | Gemini | `https://generativelanguage.googleapis.com/v1beta` | `gemini-2.0-flash` |

   点「服务商预设」里的按钮会自动填好地址和模型；再粘 API Key，点 **测试连接**。
模型名可以直接手输，也可以点右边的 **拉取列表**——它会向接口的 `/models` 拉一次，
把可用模型做成候选与一排芯片，点一下就能切换（第一次打开设置或测试连接成功时会自动拉）。

3. 回到游戏，在「白宫战情室」里写一句话，例如：

   > 今晚黄金时段发表全国电视讲话，宣布把处方药价格上限写进行政令，并要求国会两周内跟进立法。

   点「执行」。AI 会告诉你：能不能做、花几个行动点、支持率与行业好感怎么变、
   制药业会不会起诉、法案有没有进起草队列。

4. 想回看 AI 记住了什么：点顶栏 **「态势」**，或战情室下方的「态势简报」——
   里面有最近行动、外部事件、承诺期限、关键人物态度与风险。AI 另有一份更详细的内部档案，
   只在提示词里使用，界面上看不到。

5. 看舆论：点顶栏 **「舆论」** 标签。上半是 8 家媒体的本期报道（各带立场），
   下半是普通美国人的信息流——平台皮肤随年代自动切换：论坛 → Facebook → Twitter → X。

## 改了哪里：从「点按钮」到「写一句话」

| 场景 | 原版 | AI 版 |
|---|---|---|
| 本周执政行动（白宫战情室） | 40 多个固定按钮（讲话 / 制裁 / 基建…） | **一个输入框**，AI 判断权限、成本与后果 |
| 竞选行动（初选 / 大选） | 固定行动目录（现场造势 / 媒体 / 筹款…） | 原按钮区隐藏，换成**一个输入框**，AI 只结算竞选数值 |
| 突发事件决断 | 2~4 个预设选项 | **自己写处置方式**，AI 裁决 |
| 重大冲击节点（金融危机 / 疫情…） | 每个节点 3~4 个预设选项 | **自己写应对**，AI 裁决后照旧推进冲击时间线 |
| 国际危机 | 每个阶段固定动词选项 | **自己写处置**，AI 裁决后照旧推进危机阶段 |
| 记录与上下文 | 只有数字和新闻流 | **态势简报**（玩家可查看：行动、外部事件、承诺、人物态度、风险）+ **隐藏内部档案**（只喂 AI） |
| 舆论 | 只有一条条新闻日志 | **舆论场**标签：8 家媒体按立场写社论 + 民间信息流（论坛/Facebook/Twitter/X 随年代换皮） |

原版按钮并没有删掉：AI 设置 → 玩法 → 勾选「保留原版内置行动/选项」，或在出错时展开
「经典内置选项」，还可以一键 `关闭 AI 模式` 完全退回原版。默认不显示，是为了让「自由输入」
成为唯一的主路径。

实现方式（为什么原版一行不用改）：扩展层在 `ai/ai-hooks.js` 里覆写 13 个全局函数——
`presActionsPane` / `campaignPane2` / `camp2ActionsHTML` / `actionButtons` / `pendingEventCard` /
`shockEvModalPane` / `crisisPane` / `modalHTML` / `fireEvent` / `mainPane` / `topbar` / `setTab` /
`doAdvance`（外加 `gearBtnHTML` 加按钮）。
原版是单文件经典脚本，函数声明是 `window` 属性，后加载的脚本重新赋值即可生效；
`AI 设置 → 玩法` 里关掉 AI 时，这些覆写直接把调用交回保存下来的原函数。

## 保留了什么：原版的数值机制

AI 只负责**产出数字**，数字怎么进游戏完全走原版管线：

| 机制 | 接入点 |
|---|---|
| 支持率、政治资本、紧张度、社会撕裂 | `applyFx` / 直接写入 `G.pres.appr` / `G.div` |
| GDP、失业、通胀、信心、债务 | `applyFx` → `econImpulseAdd` 进**经济冲量队列**，分 12~26 周释放，有周上限与错峰拆分 |
| 联邦赤字 | `G.econ.def`（占 GDP 比重，0~30） |
| 双边关系 / 行业好感 | `fx.rel` / `fx.corp` |
| 法案 | `makeCustomBill` → `G.drafts`，由原版 `billScheduler` 推进、`voteOnBill` 表决、`signBill` 签署 |
| 竞选 | `ensureCamp` / `campStatAdd` / `stateLift`，八个竞选数值一个不少 |
| 冲突局面 | 冲击：`_shockResolve` 记账（应对进度、冷却、结局判定）；危机：阶段推进 + 冷却 |
| 存档 | `G.aiLog` 与 `G.drafts` 都是普通字段，随原版存档一起保存 |

顺带保留的还有：总统任期与连任、选举人团、初选日历、国会席位与 60 票门槛、
最高法院与司法审查、州级经济与情绪、随机事件池、核战终局、UI 时代皮肤（2000→2024 七套）。

## AI 怎么结算：四道关

模型返回的 JSON 不会直接进引擎，`ai/ai-adjudicate.js` 会过四关：

1. **白名单 + 类型校验**：只认 `approval / gdp / unemployment / inflation / confidence /
   stock / deficit / debt / tension / division / politicalCapital / relations / sectors /
   bill / flags / campaign`；其余字段丢弃，字符串数字强制转 `number`，
   未知国家 ID、未知行业 ID、非法法案主题一律剔除或回落到安全值。
2. **分项硬上限**（× 严格度倍率）：

   | 字段 | 单次上限 |
   |---|---|
   | 支持率 | ±6 |
   | GDP | ±0.30 |
   | 失业 / 通胀 | ±0.30 / ±0.20 |
   | 信心 / 股市 | ±6 / ±6% |
   | 赤字 / 债务 | ±0.30 / ±0.20 |
   | 紧张度 / 撕裂 | ±12 / ±5 |
   | 政治资本 | ±8 |
   | 单国关系 / 单行业 | ±15 / ±10 |

3. **执行档位折算**：成败完全由模型返回的 `success` 档位决定，引擎**不再掷骰子**——
   同一档位永远是同一个结果（`variance` 只影响 ±22% 的数值扰动，不影响成败）：

   | `success` | 含义 | 有利效果 | 不利效果 | 行动点 |
   |---|---|---|---|---|
   | `"none"` | 未执行：越权 / 事实不可能 / 时代错位 / 元指令 | 全部丢弃 | 全部丢弃 | 不扣 |
   | `"fail"` | 执行失败：做了但没达到目的，甚至立即遭反制 | ×0.35 | ×1.10 | 照扣 |
   | `"partial"` | 部分成功：办成一半，或办成了但代价明显 | ×0.70 | ×1.00 | 照扣 |
   | `"success"` | 成功：按指令达成 | ×1.00 | ×1.00 | 照扣 |
   | `"triumph"` | 大成功：超出预期，阻力被压过去 | ×1.15 | ×0.85 | 照扣 |

   「有利 / 不利」看的是对总统有利还是有害，不看数字正负：失业率 `+0.3` 走「不利」系数，
   紧张度 `-5` 走「有利」系数。旧字段 `ok` 仍然兼容（`true → success`、`false → none`）。
4. **总量预算**：一条指令的加权影响总和不超过 `3.2 + 2.0 × 行动点`；
   超了整体等比缩小。这样「一次行动解决所有问题」在数学上不可能。

`success:"none"` 时不动任何数值、不扣行动点，只返回一句白宫式解释和替代路径。
`fail / partial` 是**真的执行了**：行动点照扣，叙事写清楚哪儿出了岔子，`followup` 给出补救方向。

## 叙事账本：AI 维护的两份账

数字只是结果，政治的另一半是「谁下了什么命令、谁在等答复、哪颗雷还没爆」。
`ai/ai-ledger.js` 让 AI 在每次裁决时同时写两份账，都随存档保存：

### ① 态势简报（玩家可见）

存在 `G.aiWorld.brief`，顶栏「态势」或战情室「态势简报」打开：

| 字段 | 内容 | 上限 |
|---|---|---|
| `summary` | 一句话形势 | 180 字 |
| `situation` | 局势要点 | 6 条 |
| `actions` | **最近行动**：你下了什么命令 → 落地成什么（带周次戳） | 12 条 |
| `external` | **外部事件**：随机事件 / 历史事件 / 危机节点的影响 | 10 条 |
| `commitments` | 承诺与期限（对谁承诺、什么时候到期、是否兑现） | 8 条 |
| `actors` | 关键人物与机构的态度变化 | 10 条 |
| `risks` | 玩家能感知到的风险（不写数值） | 6 条 |

外部事件**不花 token 也会入账**：扩展层包了原版的 `fireEvent`，随机事件、历史事件一发生
就自动写进 `external`，玩家立刻能在简报里看到「这周世界发生了什么」。

### ② 内部档案（玩家不可见）

存在 `G.aiWorld.dossier`，**不在任何界面上渲染**，只喂给模型：

| 字段 | 内容 | 上限 |
|---|---|---|
| `facts` | 隐藏事实（白宫不知道 / 不愿承认的） | 28 条 |
| `chains` | 因果链（A→B→C，几周后才显形） | 14 条 |
| `agendas` | 各方真实议程（谁想干什么、用什么手段） | 12 条 |
| `ticking` | 定时后果（还没爆的雷，含触发时间） | 14 条 |
| `profile` | 玩家画像（行事风格、软肋、基本盘） | — |
| `notes` | 裁决者笔记 | 24 条 |

提示词里两段都带：`【态势简报】`（standard 约 300 字）+ `【内部档案】`（按上下文深度取 4/8/全部）。
这样 AI 接着自己写下的账往下演，不会每轮重新发明世界。

### 维护闭环

1. **每轮增量**：裁决 JSON 里的 `ledger` 只写 1~2 条新痕迹，代码负责打周次戳、按文本去重、按上限截断。
2. **定期整理**：每 N 次裁决（默认 5），后台静默发一次「整理」请求，让模型把两份账**整体重写**一遍——
   合并重复、删掉已过期或已爆发的、保留仍在生效的。也可随时点「整理态势」手动触发。
3. **离线兜底**：整理失败或没配接口时，用本地规则去重压缩，绝不丢账、也绝不清空。
   模型返回结构不对（比如又给了一份裁决）时直接拒绝落盘。

## 舆论场：媒体社论与民间信息流

顶栏新增 **「舆论」** 标签，两块内容，全部由 AI 按当前局势生成：

### ① 媒体：一次只看一家，下拉切换

按年代给出 8 家媒体（另有 4 家会在相应年代加入），每家立场固定、腔调固定：

| 媒体 | 立场 | 腔调 |
|---|---|---|
| 纽约时报 / 华盛顿邮报 | 自由派 | 制度、调查报道、道德姿态 |
| 华尔街日报 | 保守派 | 自由市场、减税、反关税 |
| 福克斯新闻 | 保守派 | 治安、移民、军队、"主流媒体不告诉你的事" |
| NPR / MSNBC | 自由派 | 长解释、专家、把政策说成存亡之战 |
| 美联社 | 通讯社 | 只写事实、数字与各方表态 |
| 今日美国 / CNN | 中间 | 民调、突发、"双方都面临压力" |
| 政治报（2007+）/ Axios（2017+） | 中间 | 谁赢谁输、要点式 |
| 布莱巴特（2012+） | 民粹右翼 | 情绪化标题、攻击建制派 |

**版面一次只显示一家**，用卡片顶部的下拉栏切换（未生成的会标「待生成」，切过去自动生成）。
每家是一整版报纸，六个固定板块：

| 板块 | 内容 |
|---|---|
| 头条 `lead` | 本期最重要的一件事，字号最大 |
| 国内 `domestic` | 州、城市、社会情绪、治安、移民、教育 |
| 经济 `economy` | 就业、物价、利率、产业、贸易 |
| 国际 `world` | 国际大事与美国的角色 |
| 总统政策观察 `policy` | **专门评价你最近的政策**：谁受益、谁买单、阻力在哪 |
| 社论 `opinion` | 编辑部署名，最尖锐，可直接下判断 |

版头有报名、英文名、口号、立场与本期基调（肯定/批评/两极/中性），以及更新周次。
提示词强制：覆盖「国内现状 / 最近政策 / 国际大事」三件事、左右翼对同一件事给出不同的因果与责任、
不许照抄上一期标题。生成是**按家进行**的——切到哪家就生成哪家，只补空的，不浪费请求；
「生成全部」会串行把 8 家都写一遍。

### ② 民间信息流（平台随年代换皮）

| 年代 | 平台 | 皮肤特征 |
|---|---|---|
| 2000–2004 | 网络论坛（AOL 政治版） | 灰底白帖、`#楼层`、`回复(12) · 查看 840`，没有点赞 |
| 2005–2009 | Facebook | 蓝色顶栏、头像圈、真实姓名、`赞 评论 分享` |
| 2010–2022 | Twitter | 白底蓝鸟、`@handle · 3小时前`、转推/喜欢 |
| 2023+ | X | 纯黑底、`𝕏`、蓝标认证、`转帖/喜欢/查看` |

每条发言带：姓名、`@handle`、州、正文、互动数、时间——**不带任何立场标签**，
信息流里也不会跳出来解释「这是 AI 生成的」或「平台特征是什么」，读起来就是一条普通的帖子。
互动数量级按平台年代自动缩放（论坛的浏览数不会被写成 400 万）。
立场只在数据层保留三分（支持 / 反对 / 中立，嘲讽与阴阳怪气并入反对），
用来控制发言的分布与面板顶部那一行「样本倾向」百分比；单条帖子不再贴标签、也不再提供按立场筛选。

### 生成与更新

- **首次进标签**自动生成一版；之后每 N 周（默认 2）推进周次时后台悄悄换一版，也可随时点「让 AI 重新生成」。
- **不联网也能看**：点「本地生成」，用模板 + 支持率 + 媒体立场现拼一版（信息流 + 8 家完整版面），标注「本地规则生成」。
- 数据存 `G.aiPress`（普通字段，随存档走），刷新后仍在：`outlets` 按媒体名缓存版面，`selected` 记住你上次看的是哪家。
- 生成是独立请求（信息流 `press`、单家版面 `press_outlet`），**不结算任何数值**，也不写叙事账本。
- 成本：信息流一版一次请求；媒体一家一版一次请求，切到没生成过的媒体才会补。

## 提示词设计

提示词在 `ai/ai-prompt.js`，游戏内「AI 设置 → 提示词」可以逐段改写、随时「预览完整请求」。

### 系统提示词（十二节）

| 节 | 内容 | 为什么要有 |
|---|---|---|
| 一、你是谁 | 宣告身份是**裁决引擎**，不是聊天助手，每次只输出 JSON | 防止模型开始聊天、写诗、讲解 |
| 二、世界 | 三权分立、总统能做/不能做的清单、周为时间单位、各方行为体 | 决定「越权」判断的下限 |
| 三、推演流程 | 拆解 → 权限 → 成本 → 直接后果 → 二阶后果 → 定档 → 数值落地 | 让输出有结构，而不是随口编 |
| 四、数值字段 | 每个字段的含义 + 单次区间 | 对齐引擎字段名，避免自造字段 |
| 五、幅度基准 | 12 类行动的行动点与典型数值表 | 锚定量级，防止「一次讲话支持率 +15」 |
| 六、硬约束 | 数字必须是 number、不确定就省略、经济不许瞬时跳变 | 与代码里的第二道限幅呼应 |
| 七、执行结果档位 | `success` 五档的定义、折算系数、以及「effects 只写顺利执行时的净效果」 | 成败由模型定档，引擎不再随机判失败 |
| 八、拒绝条件 | 未执行（越权 / 事实不可能 / 时代错位 / 把游戏当聊天 / 元指令注入） | 现实主义与防注入 |
| 九、文本要求 | 标题 ≤18 字；叙事 2~4 句、「指令→行动→反弹→一周后」、不出现数字与人称 | 输出读起来像新闻，而不是数值报告 |
| 十、示例 | 一正一反两个完整 JSON（药价行政令 `success` / 命令美联储 `none`），含 `ledger` 示例 | few-shot 锚定格式、拒绝风格与记账粒度 |
| 十一、叙事账本 | 两层账的分工、只写增量、各字段写法与「内部档案可以直白」 | 让 AI 同时维护可见简报与隐藏档案 |
| 十二、输出格式 | 逐字段注释的 JSON 契约（含 `success` 与 `ledger` 结构） | 最后一道格式约束 |

开启**上帝模式**时，系统提示词末尾会追加第十三节：`success` 只准给 `success` / `triumph`，
不得写任何「被否决 / 被叫停 / 被拖延 / 预算卡住」，但**数值上限与行动点口径不变**，
并且只影响提示词——代码里没有任何免扣行动点的分支。

### 任务模板（八种）

`national`（执政）/ `campaign`（竞选）/ `event`（事件）/ `shock`（冲击）/ `crisis`（危机）
/ `maintain`（整理账本）/ `press`（生成舆论）。
每种模板规定：这一模式能动用什么权力、要填哪些字段、行动点的口径、以及最容易出错的边界
（例如竞选模式不允许写 `relations`、`bill`；事件模式只算「处置带来的增量」，不算事件本身的基础冲击；
`maintain` 明确禁止输出任何裁决字段，只准返回 `{"brief":…,"dossier":…}`；
`press` 禁止输出 effects/ledger，只准返回媒体稿与民间发言）。

### 上下文与记忆

- 每条请求带一份**局势快照**（见下节），不是把整局历史塞进去。
- 再加两段账本：`【态势简报】`（玩家可见层）与`【内部档案】`（隐藏层，按深度取 4 / 8 / 全部条目）。
- 「玩法 → 前情提要 / 剧情记忆」是一段自由文本，每次请求原样附上，用来维持长线连贯：
  > 本局我走的是里根式减税路线，但与工会关系极差；2022 年中期选举后众议院归共和党。

### 解析失败怎么办

返回不是合法 JSON 时，客户端会自动带上「只输出 JSON」的修复指令重试一次；
再失败就交给离线规则或报错，绝不把半截文本写进数值。

## 设置项说明

「AI 设置」四个页签：

**接口**：服务商预设（含 OpenCode / DSH 网关）、协议（OpenAI 兼容 / Anthropic / Gemini / 自定义）、
模型（手输 + **拉取列表** + 候选芯片）、base URL、Key、
温度、最大输出 token、超时、测试连接、**改用本地代理**。

**提示词**：系统提示词与六个任务模板逐段编辑、恢复默认、预览完整请求（含 token 估算）。

**玩法**：
- 上下文深度 `lite/standard/deep`
- 叙事风格：白宫纪事 / 通讯社快讯 / 政治小说
- 数值严格度：0.4~1.6 倍上限（保守 ↔ 宽松）
- 数值随机扰动 ±22%（只影响力度，不影响成败）
- **上帝模式**：行动不会失败或被阻碍。只改提示词——行动点照常消耗、数值上限与预算照旧
- 接口不可用时用本地规则裁决（离线兜底）
- 保留原版内置行动/选项（折叠备用）
- **叙事账本**：是否把账本喂给 AI、是否自动整理、每几次裁决整理一次
- **舆论场**：是否自动更新、每几周换一版、民间发言条数（8~14）
- 前情提要 / 剧情记忆

**状态**：当前协议、Key 掩码、累计请求与 token、**叙事账本条目数**（两层分别统计）、
最近一次请求诊断（端点 / 耗时 / 尝试次数 / 错误）、最近 10 条裁决档案、
「查看态势简报」「立即整理」「恢复全部默认设置」。

## 常见问题

**Q：点了执行没反应 / 一直转圈？**
先看「状态」页的最近一次请求。常见原因是 Key 错、模型名错、或该服务不允许浏览器直连（CORS）。
用 `node ai/proxy.js` 起本地代理，或在设置里点「改用本地代理」，接口地址变成
`http://127.0.0.1:8787/v1` 即可绕过 CORS 并隐藏 Key。

**Q：用 OpenCode / 内部网关的 key，浏览器里一直「网络请求失败」？**
那是 CORS：该网关不返回 `Access-Control-Allow-Origin`。设置里点「改用本地代理」，
然后在 `ai/proxy.config.json` 里写：

```json
{ "upstream": "https://opencode.ai/inference/go/v1", "apiKeyEnv": "OPENCODE_GO_API_KEY", "authStyle": "auto" }
```

`apiKeyEnv` 让 key 从环境变量读（不落到配置文件里）；`authStyle` 取 `auto | bearer | x-api-key | none`，
`auto` 时含 anthropic 的上游或 `sk-ant` 开头的 key 走 `x-api-key`，其余走 `Authorization: Bearer`。
代理同时转发 `GET /v1/models`，所以「拉取列表」也能用。

**Q：上帝模式为什么还扣行动点？**
因为它是**提示词层**的开关：只让裁决引擎不再写「被否决 / 被叫停 / 被拖延」，`success` 只给
`success` / `triumph`。行动点消耗、数值上限（±6 / ±0.3…）、总量预算全部照旧，
`ai-adjudicate.js` 里没有任何「上帝模式免扣点」的分支。

**Q：提示「两次返回都无法解析」？**
模型没按要求输出 JSON。换更强的模型、把温度降到 0.4 左右，或在提示词页把输出格式那段加强。
解析器已能容忍 ``` 围栏、前后废话、尾逗号、`//` 注释、被截断的尾巴。

**Q：AI 判得太大 / 太小？**
先调「数值严格度」，再考虑改提示词里的「幅度基准」表。代码里的分项上限是硬约束，改提示词也突破不了——
要突破得改 `ai-adjudicate.js` 的 `CAP`。

**Q：token 不够用（8k 模型报超长）？**
上下文切 `lite`、最大输出降到 800、系统提示词精简（提示词页可改）。系统提示词约 4000 token，
上下文 standard 约 700 token，输出 300~600 token。

**Q：出现 429 / 5xx？**
客户端会自动重试一次（间隔 1.4 秒）。仍失败就等一会儿，或换模型。

**Q：没有 Key 能玩吗？**
能。默认开启离线兜底：关键字规则（讲话 / 制裁 / 军事 / 刺激 / 医保 / 移民 / 集会 / 广告…）
按原版行动的量级给出效果，结果卡片会标「本地规则」。它只保证游戏能继续，不保证叙事质量。

**Q：老存档能用吗？**
能。AI 层只新增 `G.aiLog` 字段，原版 `loadGame` 不校验未知字段。存档里没有 `aiLog` 时按空处理。

**Q：AI 会不会把游戏改坏？**
所有写入口都限幅并走原版函数；关系/行业/州/国家 ID 白名单校验；法案主题白名单；
数值一律 `number`；拒绝时不落任何数值。就算模型返回垃圾，最坏结果也是「这次没效果」，不会崩档。

## 安全提醒

- API Key 存在**本机浏览器的 localStorage** 里，只在你的浏览器直接发给服务商，不经过任何第三方服务器。
- 但它仍然以明文存在本地：公用电脑上别填；上线到公网站点时更建议走 `ai/proxy.js`
  （Key 只存在服务端进程里，页面里填个假值即可）。
- `ai/proxy.js` 只监听 `127.0.0.1`，不要改成 `0.0.0.0` 暴露到公网。

## 「重度依赖」主题的字体与缺字兜底

raincandy 主题原本只用**丁卯点阵体（Dinkie Bitmap）**。官方只发布 7px / 9px 试用版（内含 2501 个汉字），
本作内嵌的 12px 子集共 2660 个字形，而游戏实际用到 2665 个字符——差 95 个
（46 个汉字如「俗 俱 價 僻 卯 叹 吻 唱 囊 宏 寓 寿 岭 怪」，以及一批符号），这些字在主题下会显示成空白。

现在改成「主字体 + 补字像素体 + 系统字体」三级栈：

```css
--rc-font:"DinkieBitmap","FusionPixel12","Zpix","MS Gothic",
          "Microsoft YaHei","PingFang SC","Hiragino Sans GB",
          "Segoe UI Symbol","Noto Sans Symbols 2","Segoe UI Emoji","Noto Color Emoji",
          ui-monospace,monospace;
```

- `FusionPixel12` = 缝合像素字体 12px Proportional SC（SIL OFL，31345 字形），与丁卯同为 12px 像素网格，
  浏览器逐字回退后视觉基本一致；68 个缺字（含全部 46 个汉字）由它补上；
- 剩下 27 个数学符号与 emoji（∓ √ ≈ ⏱ ♻ ⚖ ⚠ ✓ ✔ ✕ ✗ 🌀 🌹 🏛 👍 💬 📊 🔁 🔥 …）交给系统符号/emoji 字体；
- 用 fontTools 逐字比对 cmap：整条栈之后**缺字 0 个**。

细节与「拿到完整版丁卯点阵体后怎么替换」见 [fonts/README](fonts/README.md)。

## 已知边界

- **一周只结算一次行动**：一条指令 = 一周的事。想「先谈判再制裁」得写成一件事的两步，或分两周做。
- **AI 不推进剧情**：它不生成新事件、不开新危机——事件池、冲击时间线、危机树仍由原版引擎按历史/随机表推进，
  AI 只在「需要你决断」的地方接管。这样既有自由，又不会让世界线散架。
- **危机树内部节点**：事件型/树型危机用自由输入结算后，走的是「通用推进」（阶段+1、冷却 3~6 周、
  按 tone 提高介入程度），不会精确跳到原版某个预设分支节点——因为分支由原版选项 id 决定。
  需要原版分支时，展开「经典内置选项」用原版按钮即可。
- **竞选辩论**：辩论的表现（`debateScore`）仍由原版 `runDebate` 骰子决定；AI 只能在你「自由竞选行动」时
  影响备战与曝光。
- **离线兜底是关键字规则**，不是小模型：它能识别 15 类执政行动与 9 类竞选行动，其余归入「一般行动」。
- **内部档案只是「玩家看不到」，不是加密**：它存在存档 JSON 里，懂技术的人解包存档仍能读到。
  它的作用是「不剧透」，不是保密。
- **账本有长度上限**：公开层每类 6~12 条、内部层每类 12~28 条，超了丢最旧的；
  靠「整理」把长线内容合并压缩。所以很早以前的细节会被合并掉，重要的应该写进「前情提要」。
- **整理会花一次请求**：默认每 5 次裁决整理一次；想省钱可以调大间隔或关掉自动整理，改成手动点。
- **舆论也是一次请求**：默认每 2 周换一版；只在你打开过舆论页之后才会自动续更，避免开局就烧请求。
  平台皮肤按年份固定（≤2004 论坛 / 2005–2009 Facebook / 2010–2022 Twitter / 2023+ X），
  同一年的快照在下次更新前不会自己变。
- **舆论与时局是两套数据**：媒体评论和民间发言不反向影响支持率——它们是对局势的**描述**，
  不是新的引擎输入。想让它影响政治，就把它的意思写进你下一条自由指令里。
